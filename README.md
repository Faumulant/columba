# Drop

极轻量、仅局域网的跨设备文件投递工具。**配对一次，此后只需要"发送到某设备"。**

当前状态：**M3（极简管理面板）已实现** — IPC + 内嵌面板 + 文本传输 + 设备上限/解锁。
M0–M2（核心链路 / 永久配对 / 系统集成）已用 PC ↔ Android 手机真实局域网验证。

## 构建

```bash
go build -ldflags "-s -w" -o drop.exe ./cmd/drop
```

产物约 8 MB，无运行时依赖。

## 稳定性打磨（2026-09-26）

已落地：
- **设备地址缓存**：daemon/CLI 记录每台设备最近可用地址，发送优先直连（实测 7.1s → 0.07s）；地址失效自动回退完整发现流程
- **磁盘空间检查**：接收端在接收前校验可用空间（预留 100MB），不足则明确拒绝
- **文件级重试**：网络类错误自动整传重试一次；逻辑性拒绝（未配对/校验失败等）不重试
- 断线中断自愈：残缺文件自动清理、信任库与地址缓存自动重载、daemon 重启后扩展自愈

明确延后（记录在案）：
- 断点续传：需协议扩展，小文件重传成本可接受，个人场景收益低
- 通知 AUMID 品牌化：系统通知横幅当前显示"Windows PowerShell"（功能无影响）
- Android MulticastLock 实测：需真机操作

## 浏览器扩展

扩展只传**网页里看到的东西**：页面、选中文本、链接、图片、视频（右键菜单），明确不做文件拖拽。

先装好扩展（一次性）：

1. `drop install` 已自动注册三浏览器的 Native Messaging 宿主
2. **Firefox**（主用，Dev Edition 路线）：面板 ⚙ 设置 → 浏览器扩展 → **一键安装**（登记扩展目录 + 尝试写签名豁免策略）→ 重启 Firefox 即出现。
   - 需要 **Firefox Developer Edition**（正式版强制签名，无法关闭）
   - 若一键后提示"策略受限"（本机注册表保护）：Dev Edition 的 about:config → `xpinstall.signatures.required` → false，一次性动作
   - 更新扩展代码后：无需任何操作（登记的是目录，Firefox 启动时读取最新内容）
3. **Chrome/Edge**：`chrome://extensions` / `edge://extensions` → 开发者模式 → "加载已解压的扩展程序" → 选 `extension/chromium/`（manifest 内置固定 key，扩展 ID 恒为 pgihdeeaofkecmpdldpagfhnehmibgkf，与宿主注册一一对应）

使用：网页里右键 → 把页面/选中文本/链接/图片/视频发送到设备（目标 = 面板选中的设备）→ 系统通知反馈结果。
链路：扩展 → Native Messaging（dropw.exe，凭据不出浏览器）→ daemon IPC → 目标设备。

## 管理面板

托盘右键 →「打开面板」（或 `drop panel`）：以 Edge App 模式弹出独立窗口（920×680）。

- **顶部左上**：目标设备下拉框（在线状态圆点；在线探测仅在面板打开时进行）
- **下方**：按分类浏览传输记录——文件 / 音频 / 图片 / 视频 / 文本，均可按"全部/收到/发出"筛选；收到的文件可打开/定位
- **文本**：纯文本以文本本体传输（协议新增文本类型），不落盘成文件；页顶输入框可直接把文字发给选中设备
- **拖拽**：文件拖进窗口任意位置 = 后台发送给选中设备
- **⚙ 设置**：接收文件夹、设备管理（✕ 移除 / ＋添加：本机显示码或输入对方码，面板上确认）
- **设备上限**：默认 3 台；设置底部「点击解锁三台限制」→ 弹窗说明"非强制付款，直接点击即可"→ 点击后永久解锁、条目消失

## 日常形态

```bash
drop install      # 一次性安装：防火墙规则(需管理员) + drop:协议 + 开机自启
drop run          # 常驻后台：托盘图标 + 自动接收 + 收件通知
```

之后资源管理器里：**选中文件 → 右键 → 发送到 → 我的手机**，后台完成传输并弹通知
（已接收的通知带"打开 / 打开所在位置"按钮）。SendTo 菜单按已配对设备自动维护。

机制说明：
- `drop sendto` 是"发送到"快捷方式的瞬发垫片：无窗口分离子进程执行发送，自身立即退出
- 通知按钮经 `drop:` 协议回调 `drop handle`，打开文件或定位到资源管理器
- 跨主机自动发现依赖防火墙入站规则（install 添加）；规则缺失时 `-addr` 直连兜底

## 配对（一次，终身互信）

```bash
# 一方（比如手机）生成配对码：
./drop pair
#   → 显示 6 位配对码，5 分钟有效，等待对方

# 另一方（比如 PC）携带码加入：
./drop pair 359226            # 自动发现对方；多台设备时用 -to 指定
#   → 对方终端显示请求方名称与指纹，按 y 确认
#   → 双方互写信任库，配对码立即失效
```

配对完成后：

```bash
./drop rename 我的手机        # 改本机名（对方看到的显示名）
./drop devices                # 已配对设备 + 在线/离线
./drop alias localhost 手机   # 给对方起备注名（显示与 -to 均优先用它）
./drop send 文件.zip          # 只会发给已配对设备
```

接收/发送/历史的用法不变；未配对设备一律被 401 拒绝。

## 已验证行为（2026-09-26）

**M4（2026-09-26，本机模拟浏览器全链路通过，待真机右键验收）：**
- Native Messaging 宿主（dropw.exe 无参模式）：扩展 ↔ daemon 转发，凭据不出浏览器
- 右键五项：页面 / 选中文本 / 链接 / 图片 / 视频 → 文本通道发送（图片/视频先传 URL，实际媒体下载列为后续）
- Chromium 固定扩展 ID（manifest 内置 key）+ Firefox gecko ID；install 注册三浏览器宿主
- Firefox 安装面板化：设置页一键登记扩展目录（HKCU 注册表）+ Dev Edition 签名豁免（策略写入失败时回退 about:config 手动一步）

**M3（2026-09-26，本机全链路测试通过）：**
- IPC：daemon 内置 127.0.0.1 服务（token 鉴权），面板为 go:embed 单页
- 文本内容类型（/v1/text）：文本本体加密传输、不落盘、入历史与通知
- 面板配对全流程：显示码 → 对方加入 → 面板弹确认 → 双方入库；三台上限拒绝/解锁放行
- 信任库自动重载：CLI 配对与 daemon 视图实时一致
- 修复：ExitOnPair 混淆导致 daemon 配对后停止接收、发现失败静默等

**M2（2026-09-26 关闭，PC ↔ 手机实测）：**
- 右键 → 发送到 → 我的手机：瞬发垫片无黑窗，后台 worker 完成传输并弹"已发送"通知
- 收件通知带"打开 / 打开所在位置"按钮（drop: 协议回调，经无窗口 dropw.exe，零闪烁）
- 发现机制双层：组播优先（快），路由器不转发无线组播时自动回退子网探测（可靠）
  — 实测本机路由器即属此类，探测兜底后右键发送全链路打通
- 通知失败也可见（"发送失败"弹窗），不再静默；SendTo 菜单按信任库自动维护
- 托盘常驻（运行时绘制图标）、开机自启、单实例；daemon 内存 ~20 MB

**M1（2026-09-26 关闭，本机双身份 + PC ↔ 手机实测）：**
- 真实配对：手机 rename 后生成配对码，PC 携码加入，手机端 y 确认，双方互写信任库
- 配对码错误拒绝 / 一次性用后即焚；自报名（而非证书 CN）入库
- 未配对设备双重拒绝：发现层提示先配对 + 服务端 401
- 设备备注名（alias）影响显示与 `-to` 匹配；配对后传输正常
- 在线/离线探测本机验证通过（跨主机在线探测受防火墙限制）

**M0（2026-09-26 关闭，PC ↔ Android 手机真实局域网双向验证）：**
- 组播发现在多网卡（VPN/虚拟机网卡）环境下正确走真实局域网网卡
- 跨真实设备双向传输：TLS 指纹 pin + SHA-256 双端校验
- 指纹 pin 实战拦截了一次错误的设备 ID（防冒充按设计工作）
- 同名文件自动改写为 `photo (1).jpg`，绝不静默覆盖
- 传输中途强杀发送端 → 接收端丢弃 `.part`，历史记为失败
- 1 GB 文件传输，内存占用恒定（io.Copy 流式）

后续待做：
- 组播发现慢时（回退探测）右键发送有 5–10 秒延迟 → M5：按设备缓存上次 IP，优先直连
- 通知横幅归属显示为 PowerShell（借用其 AUMID）→ M3 注册自有 AUMID
- Android 接收组播（MulticastLock）未测 → M5

## 设计决策（已确认）

| 决策点 | 结论 |
|---|---|
| 技术栈 | Go 单二进制；除 golang.org/x/net 外零第三方依赖 |
| 发现 | UDP 组播（224.0.0.240:42708），不用 mDNS 库 |
| 加密 | TLS 1.3 双向证书指纹互认；配对码仅作授权凭证 |
| 接收行为 | 已信任设备自动接收，仅弹通知 |
| 浏览器扩展 | Firefox（主用）+ Chrome/Edge，Native Messaging → 本地 daemon |
| 协议契约 | [docs/protocol.md](docs/protocol.md)，未来手机端按此实现 |

## 目录结构

```text
cmd/drop/          CLI 入口（id/discover/receive/send/history）
core/protocol/     线上消息与契约（平台无关）
core/identity/     设备身份、信任库、TLS 指纹互认
core/discover/     UDP 组播发现（逐网卡加入与宣告）
core/transfer/     清单、流式上传、.part+SHA-256+原子改名、同名冲突
core/history/      本地传输历史（JSONL）
docs/protocol.md   协议规范
```
